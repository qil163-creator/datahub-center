# Modeling 模块约束

本文件适用于 `yudao-module-modeling/**`，与仓库根 `AGENTS.md` 同时生效。

- Modeling 拥有逻辑模型、当前字段与类型配置、部署执行记录和领域状态；跨模块合同放在 `modeling-api`，实现放在 `modeling-server`。
- 数据库产品识别、标识符、类型映射、元数据、通用 schema diff、DDL 计划与执行优先复用 DB Switch。业务侧只保留模型语义、当前设计/CAS、审批、数据源解析、部署编排和错误翻译；不得维护第二套方言 switch 或 JDBC 元数据实现。
- 使用 DB Switch 前按“数据库产品 × metadata/DDL/read/write/sync”核对实际注册、驱动、实现、调用方和测试。未验证的矩阵单元必须显式 unsupported，不能从已有枚举推断可用。
- 模型部署是外部数据库副作用，不属于平台本地事务。先持久化可恢复的部署意图/状态，再执行外部操作并记录确定、失败或未知结果；重试必须幂等，差异计划、执行记录和最终数据库状态必须可对账。
- 当前设计由主模型与字段表共同维护，revision 仅用于乐观锁。逻辑模型每次发布、业务实体每次上线，在同一事务内生成不可变版本快照，只用于查看与比对，不写回当前设计；已有部署执行记录仅冻结该任务必需的输入与产物，必须可重复解码且不能被后续设计覆盖。涉及发布、部署或回滚的状态迁移使用 CAS/锁并验证真实事务代理边界。
- 物化部署与指标查询以 PostgreSQL 和 Doris 为已验证目标；Doris 按原生关系身份定位目标并在执行后复验，非事务 DDL 的中途失败保留未知结果并对账，键、分区、分桶变更等未验证路径显式拒绝。
- 对用户选择的目标数据源动态 DDL 不创建平台迁移；若同时改变平台模型表、字典、菜单、权限或修复数据，平台部分仍提交新的全局编号 PostgreSQL 迁移。
- 方言输出和 schema diff 使用聚焦契约测试；实际 DDL、原生类型、事务/锁和迁移重放使用真实目标数据库/Testcontainers，不以 H2 代替。
