# PostgreSQL 脚本与迁移约束

本文件适用于 `sql/postgresql/**`，与仓库根 `AGENTS.md` 同时生效。

## 文件归类

- `datahub-center.sql` 是新库全量基线；已有数据库只能执行新的编号迁移，不能重新导入全量基线。
- 历史未编号脚本保持原名、原路径，不追溯移动、重命名或纳入新编号。测试夹具必须留在对应模块的 `src/test/resources`。
- 今后由仓库发布和管理的平台表、列、约束、索引、序列、字典、菜单权限、初始化数据或数据修复，全部进入 `sql/postgresql/migrations`。
- 对用户目标数据源动态生成或执行的 DDL/搬数走 DB Switch；只有同时改变平台自身持久状态的部分才创建仓库迁移。

## 全局编号

- 文件名固定为 `NNNN_<module>_<short-description>.sql`，四位十进制前缀在整个 migrations 目录全局唯一。
- 创建前运行 `python tools/quality/check_migrations.py --next`，取现有最大编号加一；同一任务有依赖的多文件使用连续编号，按结构、必要数据/字典、菜单权限、修复回填的真实依赖排序。
- 合并或交付前重新扫描并解决并行分支冲突。只有尚未交付且属于当前任务的新文件可以重编号或原地修改。
- 已合并、发布、交付或可能执行过的迁移不可修改、重命名、删除或复用编号；修复必须创建更大的新编号。

## 文件内容

- 文件头必须包含 `Migration`、`Purpose`、`Depends on`、`Target`、`Repeatable`、`Rollback`，并如实描述前置状态、事务边界、不可逆操作和恢复方式。
- 增量脚本必须可独立执行并包含完成该状态所需的全部 SQL，不以伪代码、生成器 `sql/sql.sql` 或人工补充说明代替。
- 优先使用 PostgreSQL 可重放、加法式写法；破坏性 DDL、大回填、长锁表或不可逆更新必须显式说明影响。创建脚本不代表获准在共享或生产数据库执行。
- 数据中台 `dh_*` 业务表使用单租户模型，不新增 `tenant_id`、租户复合唯一键或租户外键；业务唯一性按全局有效记录约束。审计字段、逻辑删除、对象/部门范围、外键/引用、索引和注释仍须保留。菜单/权限值必须与后端注解和前端授权字符串一致。
- `system_*`、`infra_*`、`bpm_*` 等脚手架租户列，以及外部调度引擎的执行用户配置不属于业务租户删除范围。历史编号迁移仍不可变；新库基线的最终状态必须与最新单租户迁移一致。
- 最终状态属于新安装时同步更新 `datahub-center.sql`，并在文件开头维护唯一的 `-- Included migrations through: NNNN`；该值必须等于当前最高迁移编号。环境执行账本应记录编号和 SHA-256，拒绝同编号不同内容。
- 最终的sql文件中注释都必须为中文注释，创建或修改表结构，必须带有中文的字段注释。

## 验证与交付

- 提交前运行 `python tools/quality/check_migrations.py` 或统一入口 `python tools/quality/run_all.py`；结构检查通过不等于 SQL 语义通过。
- PostgreSQL 专属语义、JSONB、部分索引、锁、迁移重放和 repeatable 声明使用真实 PostgreSQL/Testcontainers 验证，不能以 H2 替代。
- 涉及 SQL 的最终交付必须单列“SQL 执行顺序”，按编号列出精确路径、适用对象、前置条件和未验证风险；即使只有一个文件也必须列出。
