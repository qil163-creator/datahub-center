# PostgreSQL 有序迁移

本目录从新编号规则启用后开始保存由本仓库发布、管理的平台 PostgreSQL 数据库需要执行的前向增量 SQL。

运行时根据用户任务对外部或目标数据源生成、执行的动态 DDL 由 DB Switch 负责，不因该动态 DDL 本身在此创建迁移。若对应功能同时改变平台自身的表、字典、菜单或其他持久状态，平台部分仍须按本目录规则提交编号迁移。

## 文件名

- 使用 `NNNN_<module>_<short-description>.sql`。
- 编号为全局四位十进制序号：`0001`、`0002`、……、`0010`。
- 本目录只放上述已编号的生产迁移 `.sql`；生成器 `sql/sql.sql`、临时脚本、自检脚本和测试夹具放在其他位置，不能混入编号链。
- 新文件编号取本目录已有最大编号加一，不按模块重新编号，不复用旧编号。
- 合并前重新检查并行分支冲突；只有尚未交付的迁移可以重新编号。

## 执行规则

1. 新库只导入 `../datahub-center.sql` 全量基线，不重复执行已包含的迁移。2026-09-20 承接时，基线包含至 `0037`，目录仅保留 `0032`–`0037`；后续实际进度以基线开头唯一的 `Included migrations through` 标记和最高迁移编号为准。服务端须提供 btree_gist、pg_trgm，执行账号须有安装权限。
2. 已有库先核验实际结构前置条件和迁移账本，再按文件名前缀升序执行适用的新增迁移；前一文件失败后立即停止，不得跳过依赖继续执行。仓库的基线承接声明不能证明任何现网库已经升级，不能用声明或全量基线代替脚本中的实际结构前置检查。
3. 历史未编号脚本保留在上级目录，不移动、不改名。新迁移依赖历史脚本时，必须在文件头明确写出完整文件名。
4. 已合并、已交付或可能已经执行的迁移不可修改、改名或删除；修正内容使用下一个编号文件。
5. 每次数据库结构最终状态发生变化时，同时更新 `../datahub-center.sql`，并在文件开头维护唯一的 `-- Included migrations through: NNNN`；`NNNN` 必须等于当前最高迁移编号。全量基线不能替代已有库的编号增量脚本。

每个迁移文件必须在第一条 SQL 语句之前写明 Migration、Purpose、Depends on、Target、Repeatable 和 Rollback；Migration 值以文件名相同的四位编号开头。交付说明必须单列“SQL 执行顺序”，列出精确路径、适用数据库状态和前置条件。
