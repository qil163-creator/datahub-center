# qData 组件配置复核与本轮验证

本轮逐项读取 qData 离线/实时配置使用的49个组件及共享字段控件源码，并与本地配置入口对照。完整结果见 [49项覆盖矩阵](verification/qdata-49-component-audit.md)。原站证据是REA取得的静态资源，不能表述为49个组件均已实际点击、运行，亦不能表述为整体已经1:1完成。

本轮实际补齐：

- 节点右键输入/输出字段、类型/长度/小数精度/步骤来源弹窗；源节点只显示输出入口，其他节点保留两个入口。读取实际连接元数据，未知内容留空，不保存流程或运行任务。
- 属性字段修改弹窗、删除确认、最后字段保护、拖拽/键盘排序，以及获取字段的三种冲突处理方式。
- 安全SQL字段解析；表输出的双列勾选、全选、拖拽、映射状态恢复与失效字段校验。普通数据库没有被误加“qData类型兼容禁选”的规则。
- CSV、Excel、JSONL受管上传和字段解析；Excel工作表及起始行列隔离；多个未知类型可逐个确认。
- Kafka平台连接、属性字段及JSON参数；Kafka `batchSize`为字节，其他消息组件的条数参数不混用。
- 计算器24种操作、派生7种操作，以及排序/拆分/常量/范围/映射/字符串/设置值/Java输出字段的辅助交互。保留历史未改的合法重复规则，不隐式重排或去重。
- 字段选择的纯选择/别名/删除会更新下游字段提示；无法证明的转换不伪造类型。只读、取消、节点/任务/会话切换均有保护。

仍未完全对齐的资产表/分批增量、WSDL、Join三步骤、行列转换方向、True/False和子流程执行契约等，逐项写在矩阵的剩余差异列。本轮没有将这些差异标作完成，也没有把配置入口当作执行引擎支持。

- [8项跨服务文件断言](verification/file-schema-api.json)通过：实际上传、mTLS读取、CSV/Excel/JSONL解析、错误格式、跨用户和缺证书拒绝等。
