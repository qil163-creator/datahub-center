# ODPS 输入组件交互核对

本轮以用户新增 ODPS 截图为视觉事实；原站静态 bundle 仅补充交互结构，未将静态源码当作运行成功证据。

本地验证使用已有 `5999` 的 `.temp/odps-input-reference/index.html` 页面。没有启动或停止服务。HTML importmap 只在该夹具页面将请求模块映射到静态桩；采集记录中实际 `/admin-api/` 请求为零，夹具保存按钮只调用前端校验。

## 已验证

- ODPS 源连接、类型、项目实例和表目录联动；表选择实际调用组件现有元数据接口。原生列长度与主键事实不自动注入不兼容的执行字段参数。
- 全量、ID 增量和时间范围增量配置；ID 开始值保持十进制字符串，校验整数；增量时隐藏主属性表并保留声明字段。
- 四列只读主属性表；字段高级操作保留。SQL/表模式切换仅提交当前分支，并在当前编辑会话恢复分支草稿。
- 时间条件的空基准、固定值、时间范围及 SQL 表达式分支；ODPS 条件弹窗宽度 912px。时间与日期格式采用既有控件的严格值转换。
- SQL 编辑器在异步加载及失败期间保留可编辑文本区；初始化失败可重试，加载期间输入与只读模式均有回归测试。SQL 基准按表达式校验，不把完整语句诊断标记当成表达式错误。

## 验证结果

- 关系输入、旧参数适配、SQL 降级、既有读取选项及真实 Antdv 控件共 5 个 Vitest 文件，25 项测试通过。
- 本轮 8 个 TS/Vue 文件通过 type-aware oxlint、eslint、stylelint 局部检查。全应用 typecheck 由主代理统一运行。
- REA 共 10 个受控场景：全量、ID、固定基准、时间范围基准、SQL 基准、主 SQL，以及 1200/1024/768/390 宽度。
- 所有场景完成，零 page-error、零 console-error、零实际平台 API 请求。1823px 场景主弹窗宽 1200px；各断点 documentWidth 均等于视口宽度。截图及 Evidence ID 见 `rea-verification.json`。

## 边界

本报告不是数据库或云端执行验收。真实 ODPS Tunnel 当前只支持受管有界表全量；SQL 作业、where 与持久增量游标沿用后端检查限制。字段解析不能把已有声明字段冒充真实查询元数据。没有发布任务、运行同步或写入业务表。

其他同族组件仅复用模块接口，当前验收优先 ODPS，未据此宣称 Hive、MongoDB、TDengine 的参考交互已完成。
