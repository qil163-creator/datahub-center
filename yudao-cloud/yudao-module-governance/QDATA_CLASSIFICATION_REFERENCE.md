## 组件、权限与引用边界

分类及类目沿用治理原领域、Controller、BaseMapperX、现有权限和动态菜单。定义为平台共享，不沿用“我的资产”的部门范围。列表、选项、详情及配置读取使用原分类查询权限；写入使用原新增、修改、删除权限，目录操作与新增分级继续使用各自权限。

检索后复用 SafetyRuleService 的发布、不可变版本、摘要核验和 SafetyMaskEngine。分类配置仅映射本分类的展示掩码；客户端不能指定其他规则编号。扩展现有引擎支持按原始位置处理多个闭区间，完整替换串替换对应区间；旧单区间协议保持。该契约是本地实现，不声称已观察到来源服务器完全相同的执行算法。

复用时修正了规则版本及替换明细 DO 与真实表名不一致的问题；JSONB 保存会规范化键顺序及空格，发布和变化比较采用 PostgreSQL 规范化文本计算摘要，读取继续验证真实摘要，不取消完整性检查。

分类、目录以及分类内的规则配置采用真实事务、修订校验和定义锁。批量分级与删除先校验全部对象，任何冲突整体回滚；本地写入清除来源更新人及更新时间，以真实本地操作审计展示。原独立类目管理页同步传播新修订，避免新页面之外的直接调用方失效。

已配置规则同时回传并校验 `ruleVersionId` 和不透明 `ruleRevisionToken`。独立规则管理页修改配置或只修改名称、状态时，旧分类弹窗均不能覆盖新结果；校验在规则行锁内执行。静态任务的规则引用计数改用参数化 JSONB 路径精确匹配，避免 JSONB 空格规范化导致漏计或把编号前缀当作同一规则。

删除使用逻辑墓碑并保护同库规则、识别规则、字段打标和目录后代引用。既有资产敏感清单保存的分类事实快照继续保留；没有新增反向计数 RPC 或跨服务事务，不宣称跨服务原子引用保护。已迁入 25 条敏感清单引用的本地分类编号保持，其真实规则关联阻止分类被误删。
