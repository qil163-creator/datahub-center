## 主数据维护

列表路由 `/dg/masterData/maintain`，详情 `/dg/maintenance/detail?modelId=5`。左侧类目树，右侧名称、编码、状态查询及展开的创建时间区间；模型列表默认查询状态 `2,3`，按创建时间降序。每行展示模型、类目、连接类型、字段数、数据量及最近维护时间。

观测接口：`GET /mdm/model/list`、`GET /mdm/modelCat/listAll`、`GET /mdm/model/{id}`、`GET /mdm/modelColumn/listByModelId`、`GET /mdm/model/data/{id}`。模型字段定义驱动列标题、顺序、类型、长度、必填及数据元展示；记录使用独立 `MDM_ID` 身份。脚本声明在同一数据资源上使用 POST/PUT/DELETE，并通过状态子资源启停记录，但本次没有执行这些写接口。

导入、查重在列表和详情中均只调用“功能正在开发中”提示，无业务请求。该结论同时有脚本及实时点击证据，不应伪造成导入完成或查重通过。项目保留其位置并明确禁用。

项目实现继续使用既有 `MasterDataService`、模型字段定义及持久提交协议。按需计数只使用已验证的数据源能力；计数失败显示未知，不能显示成零。维护专用读接口使用 `governance:master-data:query`，平台内共享可见；写操作继续由独立权限、模型可维护状态、主键和审批/幂等协议控制。大整数及精确小数不经过 JavaScript 有损数值转换。

## 主数据推送

列表路由 `/dg/masterData/push`，详情 `/dg/mdm/push/detail?id=4`。列表根据下游系统和最近推送结果过滤，展示模型、范围/模式标签、接收地址、最近执行统计、启停及更多菜单。详情包含 REST 接收配置、字段映射、推送日志、详细信息四页。

观测接口为 `GET /mdm/push/list`、`GET /mdm/push/{id}`、`GET /mdm/pushColumnMapping/list`、`GET /mdm/pushInstance/list`。脚本声明 POST/PUT `/mdm/push`、DELETE `/mdm/push/{id}`、POST `/mdm/push/push/{id}`、POST `/mdm/push/restPush/{id}`。启停通过部分更新 `validFlag`，不能据此推断其服务端调度方式。

实时下拉选项：范围“启用数据/全部数据”，模式“增量推送/全量推送”，方法“POST/PUT/GET”，认证“Token”，自动重试“否/是”，耗尽处理“停止任务/转人工处理”。默认超时 30 秒、重试 3 次、间隔 5 分钟。Token 有提交时必填校验，至少要求一条映射。映射由是否推送、源字段、目标字段、原值/标准字典转换、默认值组成。编辑时范围、模式被禁用。

## 项目适配与能力归属

检索并复用已有 `MasterDistributeService`、持久运行协议、`MasterDistributeJob`、JDK 单次发送 HTTP 路径、DB Switch 数据读取及字段类型协议。业务层负责范围、标准字典、字段映射、运行状态及增量检查点，不重复实现数据库方言或通用连接器。既有数据库和 MQ 派发入口保留，REST 作为本次默认业务展示。

项目模型没有 qData 强制预设的 `STATUS` 列，启用范围必须显式选择状态字段与启用值。不能借模型发布状态替代记录状态，也不能静默退化成全量。增量基于模型主键及映射结果摘要，只有已确认成功的批次推进检查点；这是项目实现选择，并非声称已逆向出 qData 服务端算法。

当前增量发送新增或内容变化的现存记录，不监听数据库日志，物理删除不会产生下游删除事件。描述、Token 和重试参数变更不清除检查点；改变目标或投递语义时才失效。人工确认完整补偿后，只清除被处置运行关联的检查点，避免漏发已撤销的数据。

发送前失败与发送后结果未知继续分开处理：结果未知阻塞任务，要求核查，不能直接盲重投。自动重试配置只作用于可证明尚未发送的失败。界面统计单列未知数，避免用“总数减失败数”伪造成功数。

HTTP 2xx 表示传输确认；非 2xx 或发送后的超时无法证明下游没有生效，仍归为未知。启用、创建已启用任务、编辑已启用任务均要求 release 权限，不能通过普通配置保存绕过启用授权。

推送 Token 存储走现有加密类型处理器，管理接口只暴露已配置标记；不得仿照参考站将认证令牌放入列表响应。请求方法按已验证的 JSON 推送协议提供 POST/PUT；GET 不作为无请求体推送的假实现。

视觉范围仅为业务内容区、弹窗和状态，不复制 qData 的浏览器工具栏、平台顶栏或左侧导航。

## SQL 执行顺序

已有平台库先满足 `0187_governance_metadata-management.sql` 的状态，再执行 `sql/postgresql/migrations/0188_governance_master-push.sql`。新库使用包含 0188 的 `sql/postgresql/datahub-center.sql`。迁移补齐请求凭据密文、执行统计和按记录检查点，不修改外部业务源表。

迁移不自动加密或迁移旧的自由格式请求配置；上线前按新表单重新保存推送配置，并使用部署环境提供的加密密钥。不得将旧配置明文留作兼容路径。
