## 权限与处置边界

配置与报告元信息按平台内细粒度接口权限可见。通用 `DatabaseApi.executeQuery` 仅支持单表受限查询，不能承接质量组件生成的函数、子查询与引用校验。本次质量抽查和问题回源从经过校验的规则模型重新生成 SQL，逐一验证当前用户对源表和引用表的完整读取范围，使用 DB Switch `QueryRuntime` 的只读、超时、行数与字节预算执行，并在返回时校验策略指纹、应用当前脱敏规则。需要行列裁剪的策略明确拒绝，权限失败不回退。问题回源使用实例快照中的对象与规则，不执行历史 `locationSql`，不能用后来修改的对象偷换数据连接。

问题弹窗每次最多展示授权结果的 1000 行，读取额外一行用于判定截断，分页和字段筛选作用于这份有界结果；截断时明确显示范围并禁止行处置，避免将窗口外的重复投影误判为唯一。处置身份绑定报告、冻结定义、当前用户、实际权限/脱敏策略指纹及授权投影内容。用户、策略、源数据或投影改变后不继承原忽略结论；完整结果中的重复投影也禁止单行处置。不用行号假冒主键，也不把返回给客户端的数据作为可信回写身份。

忽略和备注先回源核验可见行，再在短事务中执行修订号 CAS，状态与包含操作人、前后状态、修订号、备注摘要和关联编号的审计一并提交。持有平台事务时不调用远端服务。批量任一行陈旧则整批回滚。

## 已确认的差异与未知项

- 原站执行策略说明包含并行、串行等待、串行抛弃、串行优先；这些文字不足以证明服务端抢占和取消协议。项目的 `SERIAL/PARALLEL` 是单次执行内的对象处理顺序，页面如实标注为“对象串行/对象并行”，没有伪映射四种调度策略。
- 正式任务执行延续既有全表统计引擎。新增评测及抽查、问题回源必须验证执行人和全部源表授权；需要行列裁剪的授权范围明确拒绝交给未实现范围改写的全表路径。脱敏在返回结果前应用，策略变化后请求失败。
- Where 条件仅支持所选检查字段的基本比较与布尔组合，不支持函数、参数或子查询。历史报告若缺少可验证的冻结评测定义，不执行历史任意 SQL 回源。
- 原站源代码中的“批量重新修复、批量撤销已忽略、批量撤销暂缓修复、批量退回问题处理”没有绑定点击动作。本项目保持禁用，不返回虚假的成功结果。
- 原站“处理”可以直接修改源数据；本项目沿用既有修复工单流程，避免绕过审批和数据权限。原站通知接口不能证明通知到达，本次“通知处理”同样衔接项目现有工单能力。
- 没有执行的日期使用空值；查询失败不会显示成零问题或成功。单点趋势仍能显示该次评分。

增量包含评测配置、报告关联字段、问题行状态和成功处置审计，并放宽审计/问题汇总的多字段串及限定 schema 的表名长度。历史质量表导出仅保留非空编号，增量补充编号唯一索引以支撑外键；存在重复编号时中止整个事务，不静默清理。索引和外键创建需短时表锁，生产执行应选择低峰。

在专属回环 PostgreSQL 实例分别验证增量、重复执行与全量基线，比较新表及报告字段的结构和约束。测试不会使用已有业务数据库，迁移文件创建不表示已经部署。
