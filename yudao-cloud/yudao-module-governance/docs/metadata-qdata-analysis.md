## 业务语义结论

- 发布与定版是两个动作。页面脚本具有独立的发布、`finalFlag`、`finalVersion` 和版本日志接口；不能以一个发布开关替代定版。
- 最新元数据允许维护业务描述等属性；源库字段名称、类型和长度等技术属性在编辑窗口只读。发布后的维护入口受限。
- 定版详情展示确定版本的结构。项目使用所选技术快照加确认时业务属性形成不可变镜像，撤销定版不改变外部源库。
- 文件页管理已采集的元数据。项目文件业务记录、配置和内容仍分别由自身领域拥有，删除元数据不删除源文件，也不调用 infra 的文件配置或文件记录。
- 浏览器证据不能证明 qData 服务端队列、锁和恢复实现。项目四种策略、并发上限、租约恢复和执行权限的确切含义见 [元数据采集运行契约](metadata-collection-runtime.md)，属于本地明确实现，不宣称还原了未取得的服务端源码。

## 组件检索与归属

- 数据库发现和表字段读取：复用启用中的 `yudao-spring-boot-starter-biz-dbswitch` 及既有数据库 API，不在 Governance 新建数据库协议客户端。
- 文件枚举：复用 `yudao-spring-boot-starter-biz-file` 的 `RemoteFileOperations`、路径规则和客户端；连接解析留在 DataForge，Governance 通过 `dataforge-api` 消费只读 manifest。
- 持久队列、状态、版本快照、业务字段及权限：属于 Governance。单租户表不增加租户列或固定租户兼容层。
- 调度：复用 XXL-Job 的 `metaCollectTaskJob` 扫描。周期推进与入队在本地 PostgreSQL 事务内完成，外部数据源读取不在持锁事务内执行。
- 前端：复用 VXE 表格、现有连接选择器、CronTab、对象请求守卫及表单；业务区域使用局部样式与截图裁切的提示横幅素材，保留本项目导航。
