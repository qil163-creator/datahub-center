# qData 脱敏规则与白名单对照记录

本轮替换项目现有脱敏规则库、脱敏白名单业务区域，保留导航。视觉依据为用户提供的九张截图；交互及数据依据为授权源页面和交付脚本。没有向来源系统提交新增、修改、删除或启停。

逐条刷新读取 52 条规则详情，业务配置与 0234 已迁入的规则完全一致，复用原规则和不可变版本，不重复建立。启用 7 条、禁用 45 条的来源状态保留。

对全部 52 个 `listByRuleId` 逐条核验，来源规则 20 有 14 条敏感记录、规则 22 有 11 条，其余 50 个为零。此前只采样到的空列表不代表所有规则均为空。0235 依照这些明确接口返回的来源身份核实资产、字段、分类及原始内容摘要，补入已迁入 25 条清单的真实 `rule_id`，不按规则名称或分类名称猜测。绑定同时推进技术修订 0→1，来源业务与审计事实保持，之后的维护、解绑和墓碑不会被迁移重放覆盖。

白名单有三条，分别为测站编码、测站精确位置、高精度空间坐标；有效期都是 2026-08-04 至 2099-12-31，来源状态均启用。用户本轮明确指定将来源公开显示主体“吴同”绑定项目已核定的稳定用户一。通过只读查询确认该用户启用、未删除且是超级管理员成员，仅绑定该用户，不向该角色的其他成员授权；远端用户二不作为本地用户编号。

## 页面与交互

规则列表支持名称、分类、状态查询，编号和创建时间排序、选择、刷新、列配置及分页。新增默认禁用，920px 弹窗复用分类页的多区间掩码字段组件；修改时分类只读。数据资产和数据查询场景可选，数据服务、底层脱敏和自定义映射沿来源禁用。启用记录不可删除，批量删除先显示可删和不可删数量，只提交禁用记录的原子集合。

规则详情是独立页面，包含信息摘要、“敏感清单”和“详细信息”页签。敏感清单通过资产提供方正式 API 查询明确规则关联，保留资产维护范围和原敏感清单详情、删除权限，不借治理查询权限越过资产对象授权。来源非空行具有详情弹窗及删除动作；本地删除仍携带修订并应用已有禁用约束。

白名单列表同样支持查询、排序、分页、选择、启停和禁用项删除。新增与修改为 800px 弹窗，详情为 800px 只读弹窗。名称最多 50，允许中英文、数字和下划线；描述最多 256。分类修改时只读，新增排除已存在白名单的分类，目录不可选。只有用户主体可选，角色和部门沿来源禁用。

选择用户弹窗宽 1000px，支持登录账号、手机号查询及多选、分页和已选回填。来源账号对用户列表接口得到 403，只能观察到空态及交付代码；本地使用 system-api 的必要字段分页契约和真实权限，不复制来源权限失败，也不拿昵称冒充登录账号。长编号保持字符串或无损 Long，表格单行省略并可查看完整值。

## 权限、授权与执行边界

规则及白名单定义属于平台共享治理策略，沿现有查询、新增、修改、删除权限。规则工作台复用 SafetyRuleService、不可变发布版本、JSONB 摘要、SafetyMaskEngine 和分类锁，不把普通算法接口改成仅支持展示掩码。保存和启停校验规则版本及不透明修订令牌；白名单更新、启停和删除使用行修订及事务，数据库触发器覆盖旧入口的版本递增，避免新旧编辑入口互相覆盖。

新工作台的直接策略授权使用独立 `AUTHORIZED` 状态，并同时要求 `USER_CONFIRMED_IMPORT` 或 `LOCAL_POLICY_AUTHORIZATION` 依据和真实本地授权事件。0235 的 `IMPORT_AUTHORIZATION` 只记录本轮用户确认迁入，不伪造来源审批人、审批结果或历史。旧的 DRAFT→PENDING→APPROVED 审批入口保留，但不能把直接授权策略降为旧状态。旧版只读取 APPROVED，因此不会在部署窗口把新增三条分类策略当作全局豁免。

三条策略仅为本地用户一、各自 CATEGORY 和 QUERY 读取契约，截止日完整包含当天；不扩成角色全体、GLOBAL、ALL、数据服务或导出授权。原全局豁免协议只有真实 GLOBAL 可以跳过整次脱敏，无对象上下文时 CATEGORY 不会变为全局。

SQL 查询从资产正式 API 获取精确数据库、schema、表和当前字段的分类事实，并将绑定修订、分类、规则及白名单决策纳入策略指纹；没有物理绑定的来源目录不能伪装成物理数据库。既有 DENY 不被白名单覆盖。资产迁入快照预览在已有对象范围校验后，从服务端清单构造字段分类并调用治理的认证掩码接口，非敏感字段及精确十进制字符串不变。缺失身份、策略通道不可用或事实变化不会放行原始敏感结果。规则应用场景区分资产展示与数据查询；规则缺失、停用或不可核验时使用本地保护性掩码，不声称已经观察到来源执行器采用同一算法。

技术复用检索覆盖 rpc、安全、MyBatis 和治理规则现有组件。证书识别复用 `VerifiedServicePeerResolver`，客户端复用 `MutualTlsFeignClients`；业务侧只保留治理服务允许列表、领域 DTO 和配置组装，没有复制 TLS 或数据库执行机制。资产事实接口只向认证治理服务开放，网关不向浏览器开放 RPC。

新增资产事实通道需要治理客户端配置 `yudao.asset.sensitive-policy.client.ssl-bundle`，资产提供方配置 `yudao.asset.sensitive-policy.rpc.peers` 中的治理服务证书指纹。快照掩码沿既有 `yudao.governance.standard-term.client.ssl-bundle` 和治理对资产服务的认证通道。缺少证书配置时拒绝调用，不为演示降级为未认证 RPC。此记录不保存真实证书、密钥、账号或连接凭据。

用户选择独立使用 `AdminUserOptionApi` 的窄接口及服务身份门禁，不向原通用用户 API 增加未认证入口。治理客户端需要 `yudao.system.user-option.client.ssl-bundle`，system 提供方需要 `yudao.system.user-option.rpc.peers` 的治理服务证书指纹；同时保留业务查询权限和系统用户部门数据范围。
