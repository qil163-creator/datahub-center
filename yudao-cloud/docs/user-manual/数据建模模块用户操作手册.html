数据建模模块用户操作手册

版本日期：2026-10-10。适用于统一表模型设计与部署功能。

当前入口包括业务分类、数据域、数仓分层、可选分析主题和表模型。业务过程、业务对象已移除，模型直接维护归属和粒度；业务分类及其分类树继续保留；本次移除概念模型、跨域说明和后台巡检。原业务过程调整说明见移除说明。协作、人工审批、检查报告归档、收件箱及变更回执也不再作为建模操作步骤。

本文提供当前用户操作方法。升级顺序、部署前置与验证结果以迁移执行手册为准；领域约定见统一设计实施说明。示例数据仅用于说明。

1. 功能导航与操作顺序

建议先完成一个模型的设计、发布、部署，再扩展同一数据域下的其他模型。

  1. 在规划中准备数据域和数仓分层；需要进一步分类时设置分析主题。
  2. 进入表模型，新建模型或从已有表结构导入。
  3. 编辑字段、粒度及表类型配置，保存草稿并检查设计。
  4. 发布当前设计版本，形成可供部署选择的固定版本。
  5. 添加部署目标，准备部署快照，预览计划后执行并核对结果。
对象 主要用途 后续操作
表模型设计 维护字段、类型、业务口径、归属与 ER 关系 保存草稿、检查、发布、修订
设计版本 记录某次已保存设计；发布后只读 查看、对比、作为部署来源
部署目标 指定某个模型对应的数据库与目标表 选择已发布版本、准备部署、查看记录
部署记录 记录一次计划、执行、核验与登记结果 排查失败、核对未知结果、跟踪登记补偿

发布设计只固定设计内容。实际建表或补充字段需要单独执行部署。 数据接入、清洗、汇总计算及调度任务在相应的数据研发功能中配置；建立模型不会自动搬运或加工数据。

2. 规划设置

业务分类

业务分类用于维护业务分类树，保留新增、编辑、启停、详情和删除功能。新建时选择上级分类，填写名称和英文缩写；负责人、责任范围和说明按需维护。责任范围用于描述业务分工，不作为账号授权依据。

调整分类父级前可查看树移动影响预览和规划变更记录；已有子分类时须先处理子节点再删除。分类树不恢复业务过程或业务对象绑定，也不是新建表模型的强制前置。当前没有模型直接归属业务分类的关系，因此分类页面的模型引用和异常统计可为零，这不表示分类数据丢失。

数据域

数据域回答“这张表属于哪类业务数据”，例如水文监测、水资源管理。根据团队约定维护名称、编码、负责人和说明。模型直接选择数据域，不再先建立业务过程或业务对象。

数仓分层

分层回答“这张表在数仓加工链上承担什么职责”，例如 ODS、DIM、DWD、DWS、ADS。分层与表类型分别选择：分层用于组织数仓，表类型决定需要补全的设计信息。

已有模型引用的分层不能随意删除；修改命名前缀时先查看影响预览。存在引用而不允许修改时，应先处理引用，不要仅修改页面上的名称来绕过限制。

分析主题（可选）

分析主题用于进一步组织模型，可按需要维护树形层级。模型可以不选择分析主题；选择后应与模型的数据域保持一致。无需为了新建一张表先补齐大量规划节点。

在规划引用或影响页面中查看相关模型、部署问题和规划变更记录。被引用的规划节点删除会受到校验；分析主题调整父级时先查看影响并确认归属。页面不再提供主题跨域说明和最近巡检结果。

3. 新建与维护表模型

手工新建

在表模型列表点击新建，填写名称、英文名、数据域、数仓分层及表类型；分析主题按需要选择。负责人、说明和粒度说明用于帮助后续使用者理解这张表。保存后进入详情，在“设计与版本”中编辑字段及表类型配置。

草稿允许分步完善；发布时会按模型归属和所选表类型校验必填信息。粒度应说明一行代表什么，例如“一个测站在一个观测时刻的一条有效雨量观测”。涉及唯一识别的字段还需在表类型配置中明确选择。

从已有表导入

选择“从已有表导入”，指定连接与来源表，再完善模型归属和业务说明。导入会读取表结构形成设计草稿。

导入完成后检查字段注释、精度、业务键和粒度，不要把来源表的技术结构直接当作完整业务口径。此操作不复制表数据，也不自动执行目标部署。

保存与并发提示

字段和表类型配置通过“保存草稿”一起保存。发布、切换版本或离开页面前先确认本地修改已保存。即时检查针对已保存的版本；有未保存内容时先保存。

如果提示模型或布局已被其他人修改，刷新后比较当前内容，再重新提交。不要反复提交旧页面覆盖其他人的修改。ER 布局与设计内容分别保存。

4. 字段与表类型口径

字段维护

每个字段至少明确英文名、类型及必要的业务说明。按类型填写长度、总精度、小数位数、可空、主键和默认值等适用项。定点数的总精度和小数位数需要明确填写，不能把历史“长度”直接当作总精度。

可关联数据标准的字段应选择实际对应的标准。关联后检查带出的类型、单位、格式和值域；必要的业务差异仍需明确维护。保存后通过即时设计检查和发布时的标准门禁核对适用规则；关联标准不会自动修复库内已有数据。独立物理版本标准比对入口已退役。

改名时直接编辑原字段，避免删除后新建一个同义字段。系统使用稳定字段标识跟踪变更；后续部署仍会检查目标数据库是否允许执行该变更。

三类主要模型

表类型 发布前需明确的内容 水利示例
明细表 组织方式、粒度描述、粒度字段、业务时间字段 一站、一观测时刻的雨量记录；业务时间取观测时间
维度表 业务键、历史策略；保留历史时还需生效与失效时间字段 测站编码唯一标识测站；明确站名或归属变化是否保留历史
汇总表 输出粒度字段、时间粒度、业务时间口径、统计口径说明；覆盖重算时还需失效分组处理 每站每日降雨量；明确有效观测、去重、补报、日界线及缺测处理

明细表还应按场景说明重复数据识别和迟到更正；维度表按需要说明未知成员和迟到数据处理；汇总表按需要记录输入模型、窗口、过滤条件和重算策略。

汇总函数不是完整口径。 “求和”无法说明哪些记录参与计算、按什么时间分组、重复与更正记录如何处理、缺测是否等于零。应在统计口径中把这些条件写清楚。

其他表类型

表类型 主要配置
贴源表 承接模式、来源业务键；增量事件模式还需事件序列字段；按需要补充来源系统、删除与保留策略
应用表 消费场景、输出粒度描述；按需要说明使用方、更新要求与兼容策略

这些配置记录设计约定，后续加工任务仍需实现对应规则。是否持续满足时效、唯一性和值域等要求，应在实际数据质量或任务运行环节验证。

5. 版本发布与 ER 关系

发布与修订

  1. 完成字段及类型配置并保存草稿。
  2. 点击“检查设计”，处理显示的问题；涉及标准的问题按提示核对标准和适用范围。
  3. 发布已保存的版本。发布成功后，该版本成为只读设计快照。
  4. 需要继续修改时点击“修订”，在新修订版上编辑并重新发布。

历史版本用于查看与对比，不直接覆盖已发布内容。选择版本对比时同时关注字段、类型配置和业务含义。旧版本缺少必要快照信息时，按页面提示修订后补全，不要用当前表类型强行解释旧配置。

模型废弃后保留历史设计和部署记录，不能继续修订或发布。删除模型前处理系统提示的引用；删除建模记录不等于删除外部数据库中的表。

ER 关系与布局

进入 ER 页面，按分层筛选模型，查看字段和关系。创建关系时选择两端模型及对应字段；复合关联需要逐项填写字段配对。修改关系或模型被其他人更新时，刷新后重新核对。

拖动节点后保存布局。节点位置只影响画布展示，不改变表结构或发布版本。

ER 关系用于表达设计中的关联，不会自动成为数据库外键。

6. 部署目标与执行

添加目标并准备版本

在模型详情的“部署目标与记录”中添加目标，选择数据库连接与目标表名。不同目标分别记录自己的部署状态；同一数据库中的同名有效目标表不能被重复绑定。

选择一个已发布设计版本，准备部署快照，再发起部署。部署目标直接使用所选设计版本的字段与口径，不维护另一套可独立编辑的字段。准备快照需要相应发布与部署权限。

只有草稿时先保存、发布，再准备部署。已存在的历史“生成物理模型”兼容入口也遵循此顺序。

预览与执行

当前新部署及仅核验操作使用已验证的 PostgreSQL 路径。即使连接列表或历史配置中出现其他数据库类型，也不代表当前新部署已经支持；以服务端计划校验为准。

  1. 选择要部署的冻结快照。
  2. 预览所选版本与实际目标结构的差异，阅读 DDL、不支持项和执行前提。
  3. 按计划确认执行建表、补充缺失字段或仅核验。
  4. 查看部署记录中的执行、核验及元数据登记状态。

计划不支持的变更不能直接执行。已部署受管字段的改名、删除，以及缺少可靠历史产物依据的变更会被拒绝；需要另行制定迁移办法后重新核对。目标表存在额外的外部字段，不会仅因设计未包含它就自动删除。

“仅核验”不执行 DDL，但仍会检查连接、引擎能力与版本依据。执行前目标结构发生变化时，重新预览，不要依赖过期计划。

结果与异常

页面结果 处理方式
执行与核验成功 确认部署记录、目标表与后续登记状态
明确失败 阅读失败阶段和原始提示，修复后重新预览；先确认是否已产生部分目标变更
结果未知或需核对 使用记录的核对入口确认目标现状；不要直接重复执行同一建表或变更操作
结构已生效、登记待补偿 跟踪该记录的元数据登记结果；无需为了登记重试而再次执行 DDL

历史部署记录保留核对能力；核对不会重新执行结构部署。

7. 即时检查与问题处理

模型详情中的“检查设计”用于核对当前已保存版本的归属、字段与类型配置及相关标准要求。结果显示在当前页面，按问题定位到字段或配置并修改，保存后重新检查。

检查通过表示本次设计检查满足其规则；实际数据库是否成功更新，以部署执行和核验记录为准。真实数据中的空值、重复、缺测和延迟，需要在实际数据质量与运行环节检查。

后台巡检队列、定时巡检配置、历史巡检结果和检查报告归档已移除。原调度中心中手动创建的 modelCheckJob 应停用，避免调用不存在的处理器；不要停用仍承担部署登记补偿的任务。

问题 建议处理
发布提示归属或类型配置不完整 补充数据域、分层、表类型及该类型的必填配置，保存后重试
操作按钮不可见或返回无权限 请管理员核对当前账号的查询、编辑、发布、部署等权限；页面按钮与后端权限共同生效
同一表名无法添加目标 核对现有部署目标，避免将同一物理表重复登记给其他模型
表结构与设计不一致 选择正确版本重新预览，确认是未部署修改、外部新增字段还是不支持的破坏性变更
规划节点不能删除 查看真实模型引用并先处理关联，不通过删除规划信息规避模型校验
保存提示数据已修改 刷新并比较其他人的修改，再提交最新草稿或布局

建模日常读写采用当前租户范围和角色权限。切换租户后重新确认模型、连接和目标；不要将其他租户的对象编号直接用于当前操作。

反馈问题时提供模型名称、版本、部署记录编号、操作时间和错误提示。不要在反馈中附带密码、令牌或完整敏感连接信息。

8. 水利示例与日常核对

以“测站每日降雨量”为例，可建立以下三个模型。名称和字段仅作示意，应使用项目真实业务编码与规则。

模型 粒度与关键配置 需要写清的约定
测站维度 业务键 station_code 测站名称或行政归属变化是否保留历史；若保留，明确生效和失效时间
雨量观测明细 一测站、一观测时刻的一条有效观测；粒度字段与业务时间选择相应字段 雨量单位为毫米；多来源是否需要增加来源键；重复上报、更正与补报如何识别
测站日雨量汇总 测站与业务日期；时间粒度为日 日界线及时区、有效观测筛选、去重、补报重算、缺测与零值的区别，以及重算后原有分组消失如何处理

先完成这三张表的字段和口径，再在 ER 中维护测站关联。发布各设计版本后绑定目标并部署。最后在数据研发中配置实际加工任务，按模型约定实现去重、分组与重算。

这样维护设计信息可以帮助后续工作：开发人员按同一粒度编写任务；质量规则识别重复业务键和缺测；使用者确认雨量单位及统计日期；变更前通过版本和目标记录确定受影响范围。只有实际任务和质量规则执行后，才能证明数据满足这些约定。

日常核对

  • 保存前：字段含义、精度、粒度与业务时间是否清楚；类型配置是否与实际数据一致。
  • 发布前：本地修改是否保存；本次检查问题是否处理；是否选中了正确设计版本。
  • 部署前：连接、目标表、冻结版本及计划是否正确；不支持项是否已处理。
  • 部署后：执行与核验结果是否明确；登记是否完成；后续研发任务是否按新结构调整。

本手册按当前工作区源码核对，并与 HTML 阅读版同步维护。它不代表已经登录用户业务环境完成端到端验收；实际自动化验证结果请查迁移执行手册。
