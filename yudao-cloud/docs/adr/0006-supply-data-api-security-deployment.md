# ADR-0006：数据 API 开放网关安全部署约束

- 状态：Accepted
- 日期：2026-09-15

## 背景

Supply 数据 API 会向外部应用开放查询、写入或转发能力。应用密钥、签名协议、匿名访问边界、第三方转发地址和访问日志都处在外部入口安全边界上，必须用部署约束与代码约束共同保证：一次性返回的 AppSecret 不进入日志，服务重启不会导致密钥不可解密，转发能力不会成为内网探测或匿名代理。

## 决策

1. AppSecret 存储加密使用平台主密钥 `mybatis-plus.encryptor.password`。该值必须由运行环境、密钥管理系统或部署参数注入，不得写入源码、SQL、测试数据、镜像默认配置或仓库内文档示例。
2. 主密钥必须稳定且可备份。服务启动后不能生成随机主密钥；否则重启或多实例部署会导致已保存 AppSecret 无法解密。
3. 缺少主密钥时，创建应用、重置密钥、市场侧创建应用等需要写入 AppSecret 的路径必须 fail closed，不得回退明文存储。
4. 历史明文 AppSecret 仅作为兼容读取路径保留。上线后应通过重置密钥完成轮换；轮换完成前，不应把“兼容明文可读”视为达标加密存储。
5. 创建应用、重置密钥和 RPC 创建市场应用只允许把明文 AppSecret 返回一次；详情、分页、列表和普通 RPC 查询不得返回明文或密文。一次性返回密钥的入口必须显式关闭访问日志响应体记录。
6. `NONE`、`APPKEY`、`SIGN` 认证方式及当前 SM3 签名串协议保持兼容不变。签名仍按既有客户端约定生成；服务端仅使用解密后的 AppSecret 参与校验。
7. `FORWARD` 类型接口必须配置 `yudao.supply.data-api.forward-allow-hosts` 显式主机白名单。空白名单表示禁止发布和执行转发接口。
8. 转发白名单以运营可控、可信 DNS 的 host 为边界。当前实现会在请求前解析该 host 并拒绝所有内网、本机、链路本地、多播和 IPv6 ULA 地址，但不会把请求固定到某个解析后的 IP，也不提供 IP pinning。部署时不得把可被第三方随意控制 DNS 解析的域名加入白名单。
9. 转发请求禁止自动重定向，且响应体按流式读取并受大小上限保护。不得先完整读取响应体再截断。

## 后果

- 生产、测试和本地环境都必须提供稳定的 `mybatis-plus.encryptor.password` 才能创建或重置应用密钥。
- 如果已有数据库中存在历史明文 AppSecret，系统仍可校验旧签名；但交付时需要安排应用密钥重置和客户端侧轮换窗口。
- FORWARD 能力默认偏保守：未配置白名单时不可用。新增外部目标需要运维确认域名所有权、DNS 可信链路和目标服务响应规模。
- 当前认证协议为兼容既有客户端而保留；若后续升级为覆盖 query/body hash、签名版本和标准 HMAC/SM2 的协议，应新增 ADR 或替代本决策中协议兼容条款。

## 例外

- 管理端向导试调仍可在已登录用户上下文中执行未保存配置，但不改变发布入口、外部网关和 AppSecret 存储要求。
- 历史明文兼容仅用于平滑升级，不允许新增绕过加密的写入路径。

## 验证方式

- 单元测试覆盖：一次性密钥返回入口的访问日志响应体关闭；主密钥缺失 fail closed；历史明文可读；SM3 签名兼容；FORWARD 白名单、本机/IPv6/多播拒绝和响应大小限制；匿名写入/转发拒绝。
- 发布前检查部署配置：确认 `mybatis-plus.encryptor.password` 来自环境或密钥管理系统，确认 `yudao.supply.data-api.forward-allow-hosts` 只包含可信 host。
- 安全审计抽查：访问日志表不得出现 AppSecret 明文或加密串；应用详情、分页、列表接口不得返回 `secret`。
