# 建模旧数据适配说明

> 本文为历史迁移记录。2026-10-10 已移除业务过程、业务对象；升级后的平台不再提供本文的过程主域治理入口。当前迁移与直接数据域归属规则见[移除说明](remove-business-process-object.md)，不要在完成移除后重新执行旧适配脚本。

本次提供平台库增量迁移，不重建业务表，不重新生成模型 ID，也不执行任何目标数据源 DDL。脚本已准备不代表实际业务库已经迁移。

## 执行前必须确认

- 确认目标库与全部租户范围，保存只读预检结果，停用建模写入并备份整库。
- 0004_modeling_planning-semantics.sql 会删除旧 domain_ids、layer_id 和两张草稿关系表。尚未执行时，使用 0013 的兼容升级路径，不再执行 0004 的破坏性清理。需要将 0004 记为被 0013 兼容替代，不能在 0013 之后补跑它。
- 已经执行 0004 时，0013 只处理仍存在的数据；没有备份的已删字段无法恢复。现有主域可能是人工确认，也可能由旧脚本推导，不能擅自清空或替换。
- 当前分支仍有历史迁移编号门禁冲突。0013 是 check_migrations.py --next 返回的新编号，但整个升级链仍需核对环境执行账本后才能发布；不得直接把所有 SQL 按目录批量执行。

## 适配规则

| 原始数据 | 处理方式 |
| --- | --- |
| 唯一且有效的显式 PRIMARY | 只回填空的过程主域；多主域、无效引用或与现有主域冲突进入异常清单 |
| 有效 SUPPORTING | 已有有效主域后迁入支撑域；保留排序和原审计字段，不把主域重复当支撑域 |
| 分类 domain_ids、分类关系、LEGACY_INHERITED | 迁入历史候选；默认不自动确认主域，包括只剩一个有效候选的情况 |
| 模型已保存的主题域与过程组合 | 同租户且实体有效时增补缺失关系；来源模型整行留档；已逻辑删除的关系不自动复活 |
| 分类树、主题树、模型目录与技术分层 | 原值保留；theme_id 不是 subject_domain_id，不按相同 ID/名称猜测对应关系 |
| 模型版本、字段定义、部署记录与发布状态 | 不修改 |

保留仍存在的旧字段/草稿表作为历史证据，新代码不再使用这些旧字段。确认完成治理后如需清理，应另建迁移，不使用旧 0004 清理。

## SQL 执行顺序

适用于已有平台 PostgreSQL 库，前置为当前 0003 所描述的基础状态及既有建模表；与 0010–0012 无直接建模数据依赖，各自升级仍须核对对应账本。

1. docs/sql/modeling-legacy-adaptation-precheck.sql：只读检查，保存输出并确认目标库和影响范围。
2. sql/postgresql/migrations/0013_modeling_legacy-data-adaptation.sql：确认备份、停写和账本后执行。

只读预检兼容尚不存在候选/支撑表的旧库；已存在候选/支撑表中的脏引用，由 0013 的异常扫描输出，原记录保留，不自动删改。

新库使用更新后的 sql/postgresql/datahub-center.sql，标记截至 0013，不再重复执行编号迁移。完整新库基线导入与业务库执行是两项独立验收，不要用基线覆盖旧库。

## 结果与恢复

- dh_modeling_legacy_adaptation_run：一次性完成账本和处理数量。
- dh_modeling_legacy_adaptation_backup：以迁移编号、来源表、租户和原 ID 保存变更前原始行，包括已逻辑删除的历史行。
- dh_modeling_legacy_adaptation_issue：适配时发现的异常与引用证据，不是实时业务状态。

异常清单出现不代表整批失败：可确定的关系会完成适配，其余保持原状等待确认。主域缺失仍会被新代码的发布校验阻止，请在业务过程页面结合原始快照确认，不绕过校验。

脚本具有完整事务与 5 秒锁等待、10 分钟语句超时；无法取得锁会失败回滚。执行成功后重放只返回完成记录，不覆盖后续人工治理、重新插入已删关系或重复备份。序列只前移，不倒退；异常回滚时可能留下正常 ID 空洞。

不要删除完成账本强行重跑；若后续导入了另一批历史数据，应基于新快照另建编号迁移。恢复备份前必须核对迁移后发生的编辑，不应直接整表覆盖。
