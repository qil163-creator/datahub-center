# 业务操作日志统一接入与验证

本次在既有 security starter 的 operatelog 能力内增加显式 `BusinessOperateLog` 注解，沿用 `OperateLogCommonApi` 和 `system_operate_log`，不增加业务日志表，不修改现有接口权限、数据范围与业务事务。

## 覆盖范围

| 业务模块 | 新增日志入口 |
|---|---:|
| 数据资产 | 89 |
| 数据建模 | 49 |
| 数据治理 | 233 |
| 数据开发 | 171 |
| 数据服务 | 23 |
| 合计 | 565 |

范围为五个模块当前管理端的新增、修改、删除、状态变更、发布、审批、授权、撤销及执行请求。具体接入与排除原因见同目录五份 `*-operations.md`。领域已有详细系统日志优先，资产集市、填报等独立审计继续保留。查询、预览、校验、连接测试和下载导出不新增业务变更记录；后台执行结果与开放 API 调用日志继续遵循各自原有契约。

## 行为

- 捕获可信操作人、请求方法/路径/IP/UA和链路上下文，业务成功且事务提交后投递日志；异常、错误结果和未实际应用的 false 结果不记成功。
- 延迟退役删除等返回 false 但已受理的操作，由接口显式声明并记录“提交请求”，不声称最终删除完成。
- 批量部分成功仅记录成功对象，空成功集合不生成成功日志；业务编号按 Long 保留，不经过前端 number 转换。
- 日志仅包含固定操作摘要与对象编号，不自动序列化请求体、响应、SQL、密码、令牌、密钥或填写内容。
- 操作内容不重复拼接业务编号；旧统一日志返回时去掉相同编号后缀，原始审计记录保持原样。业务编号继续独立展示、筛选。
- 现有日志链路采用提交后尽力投递；投递失败有脱敏告警，不回滚已提交业务。目前没有增加持久化重试或 outbox，不能承诺日志服务故障期间零丢失。
