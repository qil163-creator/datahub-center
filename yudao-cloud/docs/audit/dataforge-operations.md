# 数据开发关键操作日志接入清单

管理端显式接入统一 `system_operate_log` 的业务写入口共 171 个，涉及 35 个 Controller。业务入口直接使用项目原有 `@LogRecord`，通过原有 `ILogRecordService` 写入；不保留自定义操作日志注解或切面。接口权限、独立领域审计和执行记录继续生效。

| 数据开发任务 | 新增、保存、删除、启停、调度设置、运行、版本回滚、实例停止/删除/人工核查 |

## 日志语义与排除范围

- 操作记录表示接口成功完成或运行命令成功受理；运行、停止等异步动作不代表后台执行已完成。
- 171 个入口均返回 `CommonResult`，成功条件为返回码为 0 且业务返回值不为 `false`。操作名保留原动作摘要，操作内容使用具体对象和关键设置，例如“创建了项目类目【名称】”“修改了项目类目【旧名】，名称从【旧名】改为【新名】”“删除了项目类目【名称】（编号【编号】）”；`extra=BUSINESS_OPERATION` 标记统一业务入口记录。
- 只提取显式的业务编号，不记录连接密码、令牌、SQL、脚本、文件内容及填报单元格值。
- 原业务编号表达式保持原含义，并直接使用 `@LogRecord.bizNo` 模板：参数编号如 `{{#id}}`、`{{#ids}}`、`{{#updateReqVO.id}}`；新建返回编号使用 `{{#_ret.data}}`，返回对象中的编号使用 `{{#_ret.data.id}}`。
- 批量对象编号交给统一组件逐个记录。远程文件操作以连接编号关联，逐项删除结果继续以业务回执为准。
- GET 查询、列表、统计、导出、下载和轮询不新增业务操作日志。
- 数据接入名称/字段/类型映射预览，数据源连接测试/诊断/只读预览，API 试调/采样，集成文件/API/WebService 字段推断，流程检查/字段推导/组件校验/Java 编译检查，整库同步校验，推送 SQL 列解析/连接测试/只读预览，以及 Excel 导入预检均不记录为业务变更。
- ETL 预览会话与取消属于短期只读调试资源，不记录为业务变更；文件批量下载同样排除。

## 对象名称与变更详情

171 个操作内容模板均包含具体名称、对象编号、状态、修订、类型、数量或返回结果。常规新增记录 DTO 名称与已提交的关键配置；修改预读真实旧名称并记录新名称和关键设置；删除、发布、状态修改和运行请求尽量通过所属业务已有 Service 查询获取名称。93 个入口使用原有 `LogRecordContext`，只放入名称、状态或名称列表，不放入完整业务对象。

预读仅用于日志：对象不存在、读取失败或调用人没有额外查询权限时，名称回退到业务编号，继续由原写入口判断权限、存在性和状态。批量删除不使用预读结果替换原请求；允许缺失对象的原行为保持不变。预读名称反映请求处理时的读取结果，不作为写入锁或并发状态证明。

复杂运行与恢复操作记录实例、批次、版本及明确的提交意图；远程文件逐项删除直接记录成功路径和失败项数量，避免把部分失败写成全部删除。可选模板表达式提供非空缺省文字，防止原始 `{{...}}` 模板被保留。填报草稿只记录版本、操作数量和操作类型，审批原因、单元格值和正文不会进入操作内容。

## 实际验证路径

优先使用项目类目的专用测试记录，无需连接外部数据源或启动任务：

1. `POST /dataforge/project-category/create`，包含 `kind=integration`、`parentId=0`、测试名称、`status=0`、`sort=0`。
2. `PUT /dataforge/project-category/update`，修改同一测试类目的名称或说明。
3. `PUT /dataforge/project-category/update-status`，修改同一测试类目的启停状态。
4. `DELETE /dataforge/project-category/delete?kind=integration&id=<编号>`，删除测试类目。
5. `GET /system/operate-log/page`，按 `bizId=<编号>` 和 `type=数据开发-项目类目管理` 查询，检查操作人、操作名、业务编号、时间与 IP。

本文件是接入清单和验证路径；实际运行环境的落库结果由任务交付说明记录。

编号表达式使用原生 `{{(表达式) ?: 0}}`，可空编号显式回退为模块范围 0；集合仍逐项处理，空成功集合不记录。
